# 2026-09-12 主线末端消融复核

被审阅文件：`docs/HANDOFF_MAINLINE_ABLATION_20260912.md`。本报告依据服务器现存 checkpoint、训练前基线、逐轮 CSV、实际代码及本次补做的最终推理。原 handoff 保留原样。

## 1. 当前结论

- **G2 是目前有较好官方成绩记录的短链候选。** handoff 转述用户提供的 G2 84.415、历史 G4b 83.945，算术正确，差值为 +0.470。本轮未访问官方评测平台，也未取得同批 G4b 重测回执，不能把它写成已经排除所有历史条件差异的因果试验。
- **G4b best 确实只是 G2 起点；这不是选优程序故障。** 训练前 epoch 0 的验证写在单独的文件，CSV 从 epoch 1 开始。此前专题文档已经明确说明过这个情况。
- **昨晚跳过 G2 的训练并非全程无收益。** 从 G1 初始化时，训练内部最优是实际训练后的 epoch 2，分数从 86.2757 升至 89.1244。将 89.1 当作 G1 初始化成绩，是 handoff 的明确错误。
- **补做部署后，没有得到“删掉 G2 已被证明更好”的结论，也没有证据宣布 G2 不可删除。** from-G1 epoch 2 相对 G2 是面积项改善、实例匹配质量下降的取舍；G1 直接部署则把这种取舍推得更远。
- 优先继续使用已有阶段权重做逐次消融。当前证据不足以支持重新设计训练、自监督模块或大规模阈值搜索。

## 2. 必须纠正的分析错误

### 2.1 选优分数与 CSV 没有矛盾

服务器原始记录：

| 运行 | 训练前 deployment_baseline | 训练期最高分 | 保存的 best | epoch 20 分数 |
| --- | ---: | ---: | ---: | ---: |
| G2 → G4b | 87.855862 | 84.548153（epoch 2） | epoch 0，87.855862 | 82.001690 |
| G1 → G4b-from-G1 | 86.275652 | 89.124409（epoch 2） | epoch 2，89.124409 | 81.764238 |

`train_affinity_geometry_g1.py` 先执行训练前验证，将结果写入 `deployment_baseline.json`、初始化 `best_score` 并保存 epoch 0；随后才创建 CSV，进入从 epoch 1 开始的训练循环。后续保存 best 与 CSV 使用相同的 `deployment["score_total"]`。

原 handoff §3.4 推测“来自另一指标、无标签 monitor 或另一图集”，不成立。`docs/AFFINITY_G4_MANUAL_GAP.md` 的“G4b 结果”一节早已同时记录 87.8559 和 84.5482，并解释 best 保留 G2。

权重实测进一步确认：

- G4b best 与 G2 best：39/39 个 geometry tensor 完全相同。
- G4b latest 与 G2 best：39/39 个不同，最大绝对差 0.0066245869。
- from-G1 best 与 G1 best：39/39 个不同，最大绝对差 0.0012257323。

因此，from-G1 的 epoch 2 是训练得到的新权重，不是保留的初始化。
86.275652 → 89.124409 是同一次运行、同代码、同实例上限的比较，其内部改善结论不依赖另做跨版本基线复现。

### 2.2 三套评测协议不能混用

| 协议 | 语义与后处理 | 数据 | 用途 |
| --- | --- | --- | --- |
| G4b 训练内部部署验证 | V6；gated/mean；high=0.55；默认 marker/vote 配方 | 历史 6 图、旧人工 GT，共 909 实例 | 保存训练 best |
| 本次固定最终部署 | E10a；gated/mean；high=0.65；seal2；low=0.45、局部重建 8 步；probability_mean；受阻分水岭 | 相同 5 图、新 GT，共 790 实例；unknown ignore | 阶段权重对照 |
| 官方成绩记录 | handoff 记录的 68 图提交 | 官方隐藏 GT | 竞赛结果，不能用代理绝对值替代 |

这里比较的两份训练 checkpoint 指 G4b 与 G4b-from-G1：其 `semantic_challenger` 均为空，`deployment_validation.boundary_threshold` 均为 0.55。历史 G1/G2 checkpoint 没有这个部署验证配置块。原 handoff 用 E10a/0.65 解释两条 G4b 训练曲线，协议不符。

历史 G4b best 停在 epoch 0，只能证明它未超过当时 **V6/0.55** 的初始选择分。不能证明 G4b 在全部阈值、语义组合或拓扑指标上无效。历史文档本身也记录了 G4b latest 改用 0.65 后的表现。

### 2.3 “只改初始化”需要区分训练更新与验证

新配置 YAML 只覆盖初始化与输出目录，但与历史 checkpoint 的完整解析配置相比还有：实例上限 255 → 65535、若干原默认参数显式化、`legacy_none` 显式化、项目路径变化。

源码检查显示：255 → 65535 也作用于 Oracle 连通分量重建。旧 CSV 将数千个原始分量合并至 255；新 CSV 保留更多分量。**两份 Oracle 的实例数、GT 惩罚 mIoU 等不能直接横向归因于初始化。**

本地 Git 可见的相关版本比较没有发现启用配置下的 affinity 损失、数据增强、采样、冻结或参数更新逻辑发生有效改变。实例上限主要影响验证和选优；训练没有按验证值调整学习率、提前停止或回读 best，因此这种选优变化不直接反馈到完整 20 epoch 的梯度更新。

这支持把初始化作为主要训练变量继续研究，但不等于已证明历史运行可逐步精确重现。历史源码快照、数据内容和运行环境仍未全部锁定。尤其不能由最终 68 图均小于 255，推断训练内部六图的选优也未受实例上限影响。

### 2.4 其他过强表述

- “epoch 2 后单调退化”应改为总体下降、中间有反弹。
- `best_val_gt_penalized_miou` 是历轮最大值，天然不下降；应读 CSV 中当前轮数值分析变化。
- 两个 epoch 20 的总分接近，不代表权重或分割结果相同。
- 一对 G2/G4b 代理变化与官方方向一致，尚不能建立“代理能排序”的普遍可靠性。
- 输出 ID 没触及 255，只排除了上限本身对那些输出的影响；没有证明其他官方评测条件从未变化。
- G4b 优化后匹配增多，不等于竞赛总分必然提高；G2 总分记录更好，也不等于其所有晶粒边界都更好。

### 3.1 新实验到底学到了什么

从 G1 到 from-G1 epoch 2，再到 epoch 20：

- 匹配数 554 → 655 → 701，GT 惩罚 mIoU 0.583 → 0.690 → 0.745。
- 铁素体预测实例 457 → 573 → 654，GT 是 459。
- 铁素体平均面积 36426 → 30034 → 26179，GT 平均面积约 37998 像素。
- 代理总分 89.53 → 81.11 → 76.42。

实测支持的解释是：**训练增加了能正确匹配的实例，同时产生更多较小的铁素体分区，平均面积项越来越吃亏。** 这是多个指标之间的取舍，不是简单“训练没学到东西”。是否主要由新增缺口负边、原生裁剪或 SAM2 配比引起，本轮没有分开消融，不能指定唯一原因。

from-G1 epoch 2 相对 G2 best：代理 +1.124 分，但有效 mIoU 下降 0.01681、少匹配 13 个实例、GT 惩罚 mIoU 下降 0.02791；面积误差改善约 3.93 个百分点。它是值得保留的短链候选，尚未全面优于 G2。

该实验虽跳过了独立 G2 阶段，后续 G4b 配方仍包含 SAM2 几何监督。因此它检验的是“能否省略这个训练阶段”，不是“SAM2 几何数据是否无用”。

面积项还可以按已知 GT 分解成 `|1 − (GT铁素体数量/预测铁素体数量) × (预测铁素体总面积/GT铁素体总面积)|`。在这五图上，G1/G2/G4b 的铁素体数量为 457/600/699，而 GT 是 459；预测铁素体总面积约为 GT 的 95.45%/98.19%/98.39%。本次平均面积差别主要体现为分区数量差别，不能把两类实例总数当作铁素体数量使用。这只是对现有标签下指标的数学分解；数量变化仍可能由边界标定、分割与类别投票共同引起，尚不能指定训练侧唯一原因。

## 4. 接下来优先做什么

1. **把 G2 best 作为缩短主线的比较基准，保留 G4b 历史锚点。** 这是依据现有官方成绩记录的实用选择，不等于本报告已经修改默认部署。
2. **继续现成权重的消融，不取消 G2 是否可删的问题。** G1 直接部署正好检验从 G2 基准继续删掉 G2；from-G1 epoch 2 则是已训练的另一条短链候选。它们都不需要启动新训练。
3. 下一步若进行候选晋级，应固定当前部署配方生成完整 68 图结果，检查边界与类别稳定性，再依据官方评估决策。G1 的强面积抵消使它尤其需要完整比较。不要把五图 89.53 当作优先晋级的充分理由，也不要仅凭匹配少就宣布其竞赛分必然较差。
4. 若要回答“历史 G4b 阶段在相同训练条件下究竟贡献多少”，才补一个当前代码、相同数据下的 G2 → G4b 对照。当前 review 不需要启动这段训练；不要先扩展成多种新损失或参数扫描。
5. 复现历史模型时保留其历史选优政策；设计新训练时，将选优规则事先固定。用户倾向损失选优，不能一边声称按损失选，一边事后用这五图挑 epoch。当前 from-G1 的 best 是部署代理选出的 epoch 2，报告必须如实标注。
