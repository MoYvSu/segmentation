## 实现与固定项

新模块：`utils/boundary_relation_inference.py`、`utils/boundary_relation_merge.py`。
入口：`tools/infer_boundary_naf.py`，不新增一套主干模型或训练分支。

- 固定原N1、旧20a59 NAF、原S0、原raw语义及final200；RGB／maps共用原C结果，仅关系权重不同。
- 读取原生RGB及连续N1／NAF，严格复用256裁窗、BORDER_REFLECT、RGB归一化和maps float16→float32训练合同。
- 从原始最终实例图枚举邻接关系，先打完分，再按分数／ID稳定排序一次选取；不反馈重算。
- 只合并当前预测类别相同的邻区，每个实例最多参与一次，不链式吞并。
- 保留较小原ID，类别继承共同原类别；不重新raw投票、不再200清理、不运行分水岭。
- 只填原始零像素中四邻接恰为这两个正ID的内部窄缝；第三方交点、宽零洞、外框原零像素保留。
- 无合法实际连接的pair明确拒绝。原实例已有多组件不强修；检查新合并确实建立A/B联系，不声称全部结果均单组件。
- 空候选／阈值0为最终实例与类别恒等，不重编号。所有结果仍是单通道uint16、ID≤65535且PNG／JSON完全对应。

关系头新增211865参数。单头推理总账在原C之上只加一次；本次双头诊断实际加载423730关系参数，不将两个独立权重算作一份。
pair评分、拒绝原因和图保留在私有audit／analysis，不混入results。

## 验收方法与结果

| 方法 | 已核实结果 | 解释边界 |
| --- | --- | --- |
| 聚焦CPU测试 | 新merge／scorer／entry与旧NAF／S0共90项通过 | 工程合同，不是得分 |
| 真实训练输入桥接 | 三个真实训练patch的原RGB、maps、masks及两种模式tensor逐值相同 | 原生预处理无悄悄改动 |
| 真实C缓存零操作 | 13源最终ID与类别恒等，原输入未变 | 验证最终输出，不只是中间残差 |
| 实际GPU合并 | 13源×2组，共26套最终PNG／JSON完成 | 未重新执行SAM2、D5a、NAF或WS |
| 独立几何核验 | 原正像素仅ID映射、安全原0填缝、第三方／外框、类别、连接合同通过 | 不证明被合并的界面物理错误 |
| 同源分布比较 | RGB／maps都明显减少F实例 | 不能把少实例当正确 |

32源训练中只有2746／21446条邻接对通过可靠关系筛选。实际应用会遇到大量训练可靠监督未覆盖的关系，
因此必须把已接受GT参照、IGNORE和测试无GT分开；不得将未知候选算作正确。

本次13源固定为9张当前测试图、2张历史无标签monitor、2张已有不完整新GT训练图，沿用旧预封列表，不按新结果重选。
9张当前图的C缓存与已交付final200 PNG／类别逐值桥接；其余复用相同冻结C缓存与原raw类别。
冷缓存一次整理成351959557字节最小输入置于快盘，后续评分、结果与过程图均在快盘；FS只作冷源读取。

## 排除一个可能解释

当前9图maps224次／RGB223次合并中，未见完整共享缝的均仅1次；其余全部共享缝都在256窗内。
两张历史图和两张已见GT图的合并全都看见完整共享缝。
因此“只看局部便删远处整条边”是工程风险，但不是本次大幅合并的主要解释。
只增加全缝可见门槛各排除1次，不能解决整体问题；本轮未据此新增门控或扫阈值。

当前RGB的169次F/F合并中，较小侧200–499／500–2000／>2000像素为20／74／75；不仅清理极小碎块。
这与训练监督的规模／类别选择偏差相容，但尚未单独证实哪个因素造成测试外推，不能直接归罪于亮度、尺度或网络结构。
