## 方案与固定项

控制C为此前已验真的全零12图，来自`runs/global_zero/candidate/`，并属于全零150图包`d484e9e1…aee30a5`的既有12张。候选U使用新增独立入口`tools/infer_unified.py`：

```text
原图原生1024滑窗，25%重叠
→ 每窗显式零噪D5a一次
→ encoder一次，共享特征
   ├─ affinity：原fusion与BlendMap拼接
   └─ semantic：原尺寸float32 logit正tent拼接，最后CPU sigmoid
→ 原整图T8/旧20a59 NAF
→ S0、原分水岭（使用拼回的局部语义）
→ 用同一局部语义概率逐实例均值投票
→ final200邻接接管一次，继承目标类别
```

不再计算全图恢复语义、全图affinity或原图全图语义。NAF仍只处理边界，实例划分和类别投票保持。当前实际backend没有独立semantic LoRA、geometry adapter或highres refiner，新入口明确拒绝这些需要不同特征的架构。

固定原backend、D5a、NAF、局部1024与重叠、affinity融合、NAF256/overlap64/kernel8、reflect32、S0、high .65/low .45、seed50及final200。唯一架构候选是语义与affinity统一使用局部恢复特征；它同时改变语义视野、输入外观与拼接，不能冒充只改变一个数值因素的因果消融。
