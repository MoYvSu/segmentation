# NAF输入线宽与训练／测试响应域差

2026-10-27。按用户要求只研究表示和缓存统计，不修改训练或推理配方，
不加载模型前向、不运行150图，不产生测试GT。GPU控制组按原计划运行，不受本次CPU检查干预。

## 结论

原文并非统一把1px细线送入NAF：作者先细化，再按数据集恢复指定线宽。
当前N1训练与固定测试缓存存在响应宽度差，主要表现为中低阈值肩部和极粗上尾，
不是高阈值核心处处同比变宽；叉口本身两域都更粗。
这支持把输入宽度作为候选因素，不证明它独自导致当前锯齿、点阵或附着闭环。

## 原文实际输入

核对日期2026-10-27，公开源码与SHA保存在私有`output/naf_width/paper/audit.json`。

| 数据集 | 推理椭圆核 | 理想水平／竖直线的字面宽度 |
| --- | ---: | ---: |
| 316L Grains | 8×8 | 约8原生像素 |
| TBM | 3×3 | 约3原生像素 |
| 4340 Steel通常图 | 4×4 | 约4原生像素 |
| 4340五张指定x50图 | 11×11 | 约11原生像素 |

规则来自[官方get_dilation_kernel_size](https://github.com/n-okt/Dual_CGB/blob/main/utils/util.py#L12-L32)。
[predict调用](https://github.com/n-okt/Dual_CGB/blob/main/test.py#L224-L236)在检测后及每次恢复后执行
[skeletonize_and_dilate](https://github.com/n-okt/Dual_CGB/blob/main/utils/image_processing.py#L78-L90)。
数据读取及推理裁块均没有resize，这些核的单位直接对应网络输入和原图像素。
复杂斜线、交点的局部宽度并不恒等于核边长。

训练合成输入不固定为8px：
[生成脚本](https://github.com/n-okt/Dual_CGB/blob/main/data_preparation/generate_broken_boundary.py#L20-L44)
取每张GT边界前景内EDT的70分位作为半径估计，
`orig_thickness=max(2,round(2*p70))`，然后在估计厚度及其增厚范围中选值，
转成奇数椭圆核，骨架膨胀后擦断。函数默认ratio=1.6，main实际传1.0。
作者原始GT未随仓库提供，因此没有在这里声称其训练宽度经验分布已知。

## 本轮度量合同

- 主对照为NAF实际使用的真实N1：32个训练源和101/116/166/169四张固定测试缓存。
  backend/restorer文件及状态SHA、来源manifest、采集脚本和相关部署配置均相同；
  局部恢复为zero/restorer。backend文件SHA前缀`13b3ab1bc509`，restorer前缀`9315da872ead`。
- 实际边界通道是`T=(B>=0.5)`。热图中低于0.5的浅肩不会进入该通道；
  0.45/0.65只作为固定阈值敏感性检查，不把调阈值视为解决方案。
- 先在原生整图计算阈值带、骨架和距离，再限定每图中央1024区域。
  不先把图缩到1024，不因裁块制造新端点。另报告原生整图作稳健性核查。
- 带宽用骨架中心到带外距离的两倍，即`2×EDT`代理；
  剔除叉口、端点邻域及图框截断，并另外检查全骨架/叉口，避免只报告规整细线。
- 主要中位/P90先按每图计算，再在源图间等权汇总；
  `>16px`占比则按合格骨架中心点池化，分母不同，不能把它称为图像比例或错误率。
- 2×EDT不是物理晶界宽，单像素直线也读2。用作者ellipse8同口径校准，
  水平线为8、45°线为10；不能把kernel8与所有实测宽度直接相除。

核心脚本为私有`output/naf_width/measure_n1_width.py`，
完整结果为`n1_width_complete.json`；叉口补扫为`junction_width_complete.json`。
两次CPU串行扫描分别85.1/82.3秒，无torch/GPU加载，未复制大缓存或修改源文件。

## 当前N1结果

下表为原生中央1024、规整骨架段上的统计。

| 固定阈值 | 训练32：典型宽度 | 测试4：典型宽度 | 较粗处P90，训练→测试 |
| --- | ---: | ---: | ---: |
| 0.45 | 10.48px | 12.49px | 14.00→17.25px |
| 0.50，实际T | 10.00px | 11.83px | 12.65→16.25px |
| 0.65 | 8.25px | 8.25px | 10.00→13.03px |

在0.5下，宽度>16px的合格骨架中心点为训练2.06%、测试11.18%；
0.65下为0.18%和1.45%。高阈值典型宽相同，不代表测试没有更粗的尾部。
原生全图而非中央区域的0.5典型宽为10.00/11.66px，趋势一致。

| 固定测试图 | T中位宽 | T的P90宽 | >16px中心点占比 |
| --- | ---: | ---: | ---: |
| 101 | 12.00 | 16.49 | 14.21% |
| 116 | 10.77 | 16.00 | 7.95% |
| 166 | 12.17 | 17.20 | 17.31% |
| 169 | 11.66 | 16.00 | 7.27% |

32个训练源典型宽度范围10.00–10.77px，116接近其上沿，不能把116的全部失败
解释为典型线宽严重异常；其宽尾仍更重。166响应占比11.73%低于训练中位12.62%，
但线更粗，说明亮响应占地、晶界密度和线宽不可互相替代。

叉口敏感性（0.5，中央区域，骨架中心池化）：

| 取点范围 | 训练中位／P95／>16比例 | 测试中位／P95／>16比例 |
| --- | --- | --- |
| 全骨架 | 10.00／15.23／3.71% | 12.00／18.11／14.38% |
| 叉口附近 | 13.42／20.00／21.20% | 14.42／22.00／35.47% |

两域叉口均更宽，测试更重的宽尾不是剔叉口筛选虚构的差异。

## N0的独立补充，不与N1混池

历史同N0的80源诊断包括GT32、其余训练随机24、旧测试按三分辨率各8共24。
按当时原生1024上下文中心512口径，额外训练24在0.45/0.65的典型宽10.00/8.00px，
旧测试24为13.11/10.00px。两域低值底部约0.0607/0.0589，差异不是训练背景完全为零。
单窗与实际拼接的宽度差中位及IQR均0，支持该历史整体宽差并非拼接主导，
不能排除局部拼接效应。来源见[原域差报告](BOUNDARY_DOMAIN_20261025.md)。

另读取新半决赛169/218/268/318四张现成N0缓存，核对模型文件/状态、运行时、
噪声、源码及部署合同与历史N0相同，仅dataset由旧100图变为新150图。
它们整图0.45/0.65源中位13.03/8.37px；按历史中心512近似同口径为12.83/8.37px，
仍主要是低阈值肩部更宽。全图0.45的P95为18.00–22.00px。
补充结果为私有`output/naf_width/new_n0.json`，CPU9.46秒，无新模型前向。

这些独立N0结果与N1方向相容，不能合并样本数、将N0数值直接当N1部署，
或把固定四图当作全150图抽样总体。

## 对锯齿和闭环的解释与边界

宽而实心、平滑的响应带不必自动成环。宽带会增加邻近支路接触和包住局部低谷的机会；
若修复输出还有点阵、多峰或双线，后续细化/种子生成便可能把这些低谷读作小腔。
这与用户观察相容，但没有在本轮作同图冻结模型的线宽干预，不能定为唯一因果。

当前重建目标允许相邻截面峰横向跳动、GT容差带内多余支路；
这是已由合成反例确认的另一因素，统一输入宽度不自动消除它。
旧synthetic-GT NAF已有加粗输入导致输出退化的干预证据，
但那是不同模型，膨胀也改变邻接，不能直接转移为当前RGB模型的因果结论。

原文更值得借鉴的是“先压成中心结构，再恢复受控线宽”，而不只是某个固定8px数值。
若下一步获授权做机制干预，应固定RGB/当前终态模型，只改变NAF边界通道的宽度表示，
同时记录改变的4/8邻接与最终种子/分隔，分开适配本身和网络作用。
它先检验敏感性，不直接晋级；若正式采用，则训练和推理共同统一，
不把训练于原宽T的模型临时喂细线当成已验证改进。
