## 实现合同

新公共`utils/boundary_input.py`提供高值边界极性的统一实现。
缺省`none`保持旧路径；启用时整张源图先阈值化、skimage骨架化、OpenCV椭圆膨胀，
训练再同步crop/D4，推理再同步pad/tile；绝不每个tile独立细化，也不按GT遮挡输入。

kernel8采用作者默认anchor(4,4)，记录anchor相对核外接框几何中心约半像素的非对称。
这不等于每种输入或最终输出都整体平移半像素；实际质心与形状、离散核有关。
该处理还可能改变近邻接触、闭环、贴框和中心位置，故称“作者式输入表示”，
不称已隔离所有拓扑因素的纯宽度因果实验，不要求预处理保持所有4/8邻接才能开训。

新`data.identity`启用时升级v2，checkpoint仍用显式训练版本和完整recipe/源SHA严格绑定；
旧checkpoint不以新代码续训，旧源码和结果保持。source_identity纳入标准化helper。

缺失集合会随新输入变化，因此：

- 保留raw_input_boundary/raw_gap_mask；固定monitor历史r4指标使用原raw T，
  继续比较同一161个缺失GT位置及同一原支持/深部输入集合。
- 标准化输入自身的missing另报`normalized_`，不能与旧控制1.481%直接混算。
- 训练日志的missing仍按实际输入归类，只作本组机制诊断；不通过改集合虚报共同缺口改善。

初始四图另算一次“标准化T直接读出、不经过NAF”，与原N1、raw T二值适配及候选分开；
不把输入形态变换本身的分隔变化全部记给网络。旧marker不复用。

### 决策

相对前两版NAF，新组是更规整、较少小F、预测面积漂移通常较轻的研究候选，
作者式输入表示值得保留。相对稳定N1尚无准确率收益证据，不直接晋级或宣称有效补边。

### 三个量必须分开

1. **输入核k**：先将原B>=0.5细化，再用椭圆模板向外扩，生成送入NAF的T。
   它改变输入带宽、近邻接触和缺口连接，不直接规定输出线宽，也没有提高输出像素分辨率。
2. **输出边界形态**：网络实际生成的单峰/多峰、宽带或多轨，是训练后需要测量的结果。
   输入缩核不保证输出等比例变窄或更准。
3. **GT容差r**：当前±2是匹配位置及近GT负例豁免范围，不是要求预测5px宽。
   改r会同时改变正匹配与负集合，与改k是不同实验。

### 缩核的机会与代价

CPU合成检查中，k8/6/4的直线横截面为8/6/4px；中心相距7px的双线在k8下连接，
k6下分离。一条线缺5px时，k8和k6仍连接，k4则断开。
因此缩核可能减少近邻误接触，同时撤回有用的输入级连接，不能只按环少来选。
这些仅为合成形态证据，不是实际NAF预测或准确率验证。

k8/6均使用偶数核和默认anchor规则，先8→6比直接改4温和；8→5还同时改变核奇偶及中心对称性。
偶核的外接框半像素非对称不是每种形状实际位移0.5px：本地CPU单点质心k8约(0.226,0.075)，
k6约(0.310,0.103)。即使保持偶数，离散椭圆也不是纯连续缩放，需记录实际几何变化。

### 定位更准也值得研究，但不是直接强贴GT像素

当前更直接的缺口是“一个横截面仍可有多条亮轨”，而非仅仅偏离GT一两个像素。
单纯收紧±2→0、恢复exact像素BCE会把GT误差直接变成惩罚，既有精确BCE路径曾出现真线被压低。
这不是说所有精确监督都无效，而是目前没有依据将其直接作为默认改进。

若缩核后仍有多轨，后续独立研究“保留位置容错，但只保留一条主脊”的目标，
例如选择一个允许偏移的潜在中心，并限制该截面的额外峰/多余质量。
仅惩罚预测均值位置还会被对称双峰骗过；交点、未知区及同截面存在另一条真实界面的区域
必须保护，不能为单峰强行抹掉细小晶粒。该单峰定位损失尚未实现或训练；输入缩核是另一次独立实验。
