## 先给结论

旧RGB通道确实被训练和使用，不能解释为零初始化后一直没有发挥作用。
当时RGB比单通道更积极改变响应，但补缺增益很弱，原边保持稍差、格点和小碎块更多。
已证实的任务缺口是两组都没有人工擦断；已证实的目标局限是容差正带允许多峰/小环。
这两点不能单独证明RGB比T-only更坏的唯一原因。

旧RGB采用raw T，当前研究控制为T8＋显式擦断。旧RGB结果不能直接否定或预言后继RGB＋T8＋擦断。
“RGB过拟合纹理/曝光”“GAN单独造成全部格点”“1000更新肯定不够”目前均未被因果消融确认。

使用旧源码、旧RGB终态及原七个256训练窗，先复现s1000的全部原`real_pair_metrics`，
误差<1e-7；再固定T/GT/valid/坐标/权重，只替换RGB。无参数更新、分水岭或测试GT。

初态RGB首层1296个权重全0，终态1296个均非0，L2变化0.648776。
初态原RGB与打乱RGB前向逐值相同；终态对RGB空间内容有明确响应。
不能由RGB首层权重较T通道小就断言它被忽略，也不能把权重范数当贡献度。

## 当前归因边界

1. 不是RGB未进入网络或一直冻结，也不是控制没跑、末期LR耗尽。
2. 原任务的输入常已有边，缺少“已有线被主动擦掉”的明确恢复任务；旧天然missing覆盖约1%。
   当前T8擦断组已4/4恢复人工分隔，说明改变任务确实能学会补缺，但自然迁移仍弱。
3. 原pointwise目标允许带内多峰，新增信息并没有自动变成唯一、规整的边界；
   相同B1又会将离散/多轨响应组织成小环。目标和读出是明确机制风险，尚未隔离为何RGB更严重。
4. RGB原图在训练/测试的模糊、亮度差异可能影响泛化；固定RGB模糊探针只提示敏感性，
   还没有训练消融证明这是旧失败主因。

### 实现前需要修正的兼容点

当前擦断实现明确限制T-only，不能只将配置切成RGB就启动。
需要允许RGB＋T8擦断，擦除仍只作用于T；smoke与monitor干净分支必须拼接同RGB＋clean T8，
而非向四通道模型直接传一通道clean T8。该改动是输入合同适配，不增加新的监督因素。
G总state SHA因1/4通道首层形状不同不会相同；应逐公共参数及T首层slice核对、新RGB权重核0，
D初态、draw、GT/valid与擦断mask仍严格核对。初态函数数值误差另核，不声称跨通道逐位等价。
