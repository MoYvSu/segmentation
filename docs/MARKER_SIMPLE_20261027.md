# 取消种子弱边重建的独立缓存对照

日期：2026-10-27。用户授权试验取消弱边重建，同时要求解释reflect的作用。
本轮只复用N1八源预测缓存，保留模型和当前部署，不训练、不跑150图、不自动出包。

## 为什么保留reflect

旧实际病例中，触框粗边界经阈值／弱重建／bridge仍能分隔两侧，骨架化后端点向图内退缩。
最明显的状态端点距左框4px，膨胀1px后仍距3px；seal2只占第0、1列，留下第2列绕行。
两侧内部因此共用种子，后续分水岭不会自行创造第二个身份。

reflect先在bridge之后将二值种子边界向外镜像32px，再细化并裁回原图，随后执行原dilate／seal。
原图边框在细化视野中成为内部位置，触框线继续到图外，有助于保留端点接触。
它不反射RGB、不增加模型推理视野、不预测缺失晶界，也没有改真实WS障碍。
seal仅封最外圈，无法修复更内侧的端点退缩；两者用途不同。

复赛同R1模型配对结果为0.8629／0.8774→0.8645／0.9006，综合提高1.240分，
主要来自面积项。这是保留reflect的实际得分依据，不代表所有细化问题均解决。
32／64宽度仅在已检查源上相同，不保证任意图稳定。
来源：AFFINITY_MARKER_PATH_20261003.md、AFFINITY_MARKER_TRIAL_20261003.md。
原定位图私存output/weak_retain/marker_path/path_detail.png与marker_reflect/compare.png。

### 必须隔离的实现耦合

直接把重建steps设0会使旧代码的marker_belt／barrier_belt共用数组，随后seal2也改变真实障碍。
因此只将原stages的high_mask作为候选marker_boundary_mask，调用同一reflect生成函数，
再把候选种子注入原N1实际分水岭。原配置仍不修改，真实高程哈希必须与N1一致。
helper为utils/marker_single_threshold.py，入口为tools/probe_marker_simplify.py；
通用缓存读写／统计／GT加载复用probe_marker_core_area.py的冻结副本，不复制输入数组。

## 后续定位：整片硬种子占地过大

2026-10-27用户希望继续针对后处理优化。本次只读既有core25检查中的N1控制回执，
没有启动新的模型、训练或分水岭。每源retained_core_pixels除以原图像素数得到：

| 统计范围 | 既有N1硬种子占比 |
| --- | ---: |
| 八源逐图，占全部图像 | 93.11%–97.59% |
| 八源像素合计 | 31324915 / 32566016 = 96.19% |
| 占最终正实例像素 | 97.43% |

OpenCV泛洪队列只扩张未标记位置，已有内部正marker保留；外框会被改为分水岭，
当前seal2已排除外框种子。因而当前分水岭主要处理约3.81%的未预分配像素。
这一占比不是准确率或面积得分；少量边界变化仍可改变整块语义投票。
