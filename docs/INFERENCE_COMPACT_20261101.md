# 保持输出一致的推理精简

2026-11-01。独立入口`tools/infer_compact.py`，默认保留已评分全零C的几何语义路径。
另支持`--geometry-mode F0`对应已交付的去底图候选；F0仍待回分，不能因为工程精简把它自动晋级。
三份模型权重、数值设置、输入尺度、融合及最终分类策略均保持原分支。
本轮不训练、不修改GT、不启用CUDA编译，不重写已交付的C/F0包。

## 改动范围

原S0读出借助诊断重放替换种子：先计算一次原种子阶段、构造reflect32种子，
重放时再计算原阶段，随后正式decode又重建阶段；F0为了构造独立核验图还额外计算一次。
这些都只执行一次真实分水岭，但会重复做细化、连通域和全图数组处理。

新`utils/compact_instance_readout.py`保留一次原阶段计算、一次reflect32种子构造及S0筛选，
直接把原有高程图和筛后种子交给一次真实`cv2.watershed`。
高/低阈值、弱响应生长、镜像边界及骨架的不同用途仍保留，没有换分割算法。

| 环节 | 精简后的行为 |
|---|---|
| 网络前向 | 原13b3 backend、9315 D5a、20a59 NAF；C/F0各自原前向保留，未换随机语义头 |
| 几何输入 | C仍用原全图恢复语义；F0仍是常数128底色＋原NAF防线 |
| 种子 | 原阶段一次，reflect32一次，S0一次；资格、位置及ID规则保持 |
| WS | 真实调用仍为一次；不进行第二次求解或新补边 |
| 临时分类 | 不再计算随后会被raw复票覆盖的语义均值；合法P0占位只用于接口，禁止直接作为最终类别 |
| 最终分类/清理 | 原raw概率、原float32取值顺序与均值函数；raw票一次，再final200一次 |
| 整数规则 | 原面积过滤、超限邻接合并、稳定面积降序及uint16重编号保持，不叠加向量化排序 |
| 包装实现 | 临时替换改普通函数，避免实验Mock持续保存逐图大数组调用历史 |

几何sigmoid保留原cat→同尺寸interpolate→二维sigmoid的布局和计算顺序；
不把近似浮点相等当阈值掩码相同，不改raw投票的归约顺序。
原始无种子/支撑筛选拒绝的失败合同保持，不增加隐式fallback。
新审计明确列出精简阶段与占位类用途，原阶段兼容性由独立桥接证明，不伪造旧诊断执行记录。

## 使用

在项目GPU环境`sam2_env`中提供原模型文件和赛方输入，输出使用全新私有目录：

```text
python tools/infer_compact.py --config config/inference/area_floor_200.yaml --dataset semifinal_150 --input-dir <150图目录> --model-dir <backend与restorer目录> --naf-checkpoint <旧20a59对应checkpoint> --output-dir outputs/compact_c --global-noise zero --geometry-mode C
```

只对F0独立候选使用`--geometry-mode F0`，其余参数保持。默认C不会取消全图恢复语义。
结果仍是`results/`下原尺寸单通道uint16实例PNG和P0/F1类别JSON；精简审计单独保存在`audit/compact_report.json`。
不接受新语义增量，不改变训练或推理默认配置；原入口及历史结果保持可回退。

## 后续CUDA编译及其余优化

先把这次等价流程稳定下来，再单独评估编译加速。编译对象应按实际剩余耗时选择：
GPU网络编译不会自动加速仍在CPU执行的OpenCV/NumPy读出；若移植后处理，还须保留骨架、
连通域、WS队列及整数编号规则。编译/移植方案独立记录冷启动和稳定运行耗时、显存与输入shape，
并核验阈值、实例和最终类别；不能因去掉噪声就默认任意编译内核或硬件逐位相同。

本轮未叠加NAF未消费RGB拷贝清理、拼接诊断方差开关、未消费全图affinity删除，
也未旁路局部D5a。这些可分别处理，防止把不同变化混成一次提速或评分结论。
全图affinity在C中未用于最终边界，但本轮仍保留其原前向；F0原本已删除它，不能重复计算收益。
