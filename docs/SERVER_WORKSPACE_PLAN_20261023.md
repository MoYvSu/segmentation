## 整理目标

用户从两个明确入口进入有监督、无监督研究；当前部署、当前控制和历史实验能快速区分。
继续开发的代码每条路线只保留一个工作入口，模型实际使用过的源码另存不可变快照。
公共原图和官方底座共用，标注、项目训练权重、伪标签与训练缓存按来源隔离。
目录整理与模型行为修改分开，不改训练配方、损失、checkpoint内容、最终推理或既有审核记录。

目录名 `supervised` 指现有使用人工标注的路线；它在比赛方法分类中属于此前的半监督方案。

## 为什么分阶段搬移

当前完整Affinity协议有1240个引用，其中1170个指向R2，另依赖fine、早期affinity、phase和公共原图。
训练预检会严格解析路径并核对内容SHA；纹理教师和语义B也各有祖先缓存、命名和控制依赖。
所以目录名像“旧实验”不代表其内容已经无用。

| 对象 | 首轮处理 | 后续实体整理条件 |
|---|---|---|
| 当前主线、控制、固定CV/phase缓存 | 原实体留在快盘，新入口链接到原位置 | 路径预检、身份及必要CPU重载均通过才考虑调整 |
| 没有路径约束且仍要使用的资源 | 校验备份后逐项迁入新布局 | 比较文件数/SHA、实际配置读取与引用解析 |
| 不再被活跃实验引用的历史组 | 先完整冷归档，再清退快盘副本 | 所有登记文件保留、归档可解包、需要时能恢复原相对结构 |
| 来源或依赖不明的目录 | 标为待查，暂留 | 不按名称、日期或失败结论直接删除 |

移动实体后让旧路径反向链接到新位置，可能改变 `Path.resolve()` 结果和协议身份；不能默认兼容。
最敏感的历史组首轮只添加新入口。原protocol/done/manifest保持原字节，不为整理路径重新生成或改写。
如果以后需要通用路径映射，应单独实现并测试，不夹带在本次文件整理中。

## 源码保存及后续实验方式

两条开发代码分别取已经核对的本地工作树/分支；主工作树存在未提交与未跟踪实现，不能只拉取HEAD就认定同步完成。
导入前列出代码文件清单，保存commit、实际工作区差异、必要未跟踪源码、配置与依赖版本；不覆盖远端独有修改。
源码归档按明确清单排除数据、权重、预测和秘密信息，不直接打包整个混合工作目录。
不使用Git发布任何赛题资产；新克隆/工作区安装现有保密防护。

后续训练复用该路线共用训练实现，实验差异用配置表达。开跑时保存一份小型精确源码快照，
输出统一放`runs/<短实验名>/`，其中包含配置、日志、checkpoint、monitor及运行记录。
这样不再每轮复制原图、底座和整库缓存，同时仍保留每个checkpoint实际使用的代码。
历史现成实验内部目录不为美观强行改成新格式。

严格无监督入口只引用官方训练原图、允许的通用基础权重及自身自动监督来源；
人工GT、人工筛选SAM64、项目有监督LoRA/头和其预测不接入无监督训练。
这里是来源与配置隔离，不是声称root用户无法访问另一条路线的文件。

## 执行顺序与验收

1. **冻结盘点快照**：再次确认没有训练/写入任务，将目录标为当前使用、控制/依赖、历史归档或待查。
2. **先完成保存**：关键模型＋实际源码＋配置/回执打包；逐项SHA核验，并验证可读取和抽样解包。
3. **建立两个入口**：先添加新目录、索引和指向旧实体的链接，检查不会误用另一条路线权重/数据。
4. **同步两套开发代码**：保留旧源码，导入审阅过的工作区快照；新实验使用新布局。
5. **逐组归档历史**：按真实引用图排除在用依赖，冷归档后核对；不直接遍历旧日期目录批量删除。
6. **CPU验收和交付**：全部在用引用可解析、关键模型SHA不变、代表checkpoint可加载、数据数量/来源一致；
   输出旧路径→新入口→归档位置对照表和快盘实际释放量。

本次无卡可完成保存、目录组织、CPU加载和预检；GPU推理及训练冒烟留恢复GPU后进行。
CPU成功不写成完整推理复现或训练resume通过。完整几何/R2原trainer未实现resume，目录整理不会改变这一点。

快盘建议争取留出约20 GiB工作空间，但可释放量要在依赖核对后计算。
大目录 `unsup_instances_20261014`（约6.05 GiB）、`unsup_proto_20261010`（约6.01 GiB）优先核查，
它们包含后续流程依赖，不代表这12 GiB可以直接删除；原固定CV约3.50 GB仍需留在快盘。
两条失效的旧净化GT链接记录为待查，不自动指向名称相近的现有GT。
