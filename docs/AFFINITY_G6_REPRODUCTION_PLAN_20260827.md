# G6 结果、阈值扫描与完整训练复现计划（2026-08-27）

## G6 判定

G6 不晋级为新主线。最佳 epoch 7 相对 G4b 在同一 high0.72/low0.45/8px 部署协议下，
六图代理总分从 83.464 升到 83.972，铁素体平均面积误差从 16.97% 降到 15.51%；但有效
匹配从 741 降到 729，GT 惩罚 mIoU 从 0.6839 降到 0.6693，有效匹配 mIoU 从 0.8390
降到 0.8345，铁素体合并数从 37 增至 43。十张测试图总实例仅由 951 变为 948，铁素体
均为 595。该损失没有像 G5 那样造成系统性实例数坍缩，但收益主要来自人工 GT 面积代理，
不能证明几何更好；继续保留 G4b。

## 0.72 不是 affinity 的固有阈值

旧边界头直接预测 `P(boundary)`，而 affinity 每通道预测
`P(neighbor belongs to the same instance)`；部署先取反并融合为边界概率，再做双阈值
marker reconstruction。因此旧边界头约 0.30 的经验阈值不能直接搬到 affinity 融合图。
当前 0.72 是强边种子阈值，0.45 是允许沿连续弱边有限生长的低阈值。

G4b 真边界融合概率均值约 0.795，q05/q10/q50 约为 0.350/0.527/0.869；实例内部均值
约 0.199、q90 约 0.625，像素 F1 最优点约 0.70。固定 low0.45、8px 重建、gated fusion、
seal2 后：

| high | 六图预测数 | 有效匹配 | GT 惩罚 mIoU | 铁素体面积误差 | 代理总分 | 十张测试实例 |
|---:|---:|---:|---:|---:|---:|---:|
| 0.60 | 1330 | 797 | 0.7313 | 28.03% | 77.687 | 1074 |
| 0.65 | 1302 | 782 | 0.7199 | 25.32% | 79.180 | 1036 |
| 0.70 | 1255 | 753 | 0.6940 | 20.78% | 81.498 | 993 |
| 0.72 | 1224 | 741 | 0.6839 | 16.97% | 83.464 | 951 |

0.72 是抑制碎片和平均面积偏差的保守点，也确实会漏掉连续但峰值不足 0.72 的真实边。
0.65 应作为强制目检/提交 challenger，但不直接替换稳定默认。单变量配置为
`config/inference/final_affinity_g4b_high065.yaml`；0.60 更可能进入过分割区。

## 完整训练复现：统一入口，内部保持课程式分阶段

单命令提交只能复现已有 checkpoint 的部署，并不等于从通用 SAM2 权重和赛方数据开始的
完整训练复现。完整复现需要覆盖语义 LoRA/decoder 和 affinity geometry；但不应从第一个
step 就把全部损失等权混合，否则容易重现多任务梯度冲突和语义能力回退。

计划实现一个可断点续训的训练编排器，由一个配置顺序执行：

1. **S0 语义复现**：初始化 LoRA 与 semantic decoder，在有类别人工数据上恢复语义头；
   旧 boundary 只在消融证明有利于语义时作为低权重辅助。
2. **S1 几何预热**：冻结语义 LoRA/decoder，用人工实例与无类别 SAM2 伪实例训练 affinity；
   该阶段复现 G4b 的稳定几何起点。
3. **S2 受控联合微调**：共享一次 encoder 前向，交替采样类别数据和几何数据；semantic、
   affinity 使用独立参数组，LoRA 只开放后层且学习率为 head 的 0.05--0.10 倍，并用冻结
   语义 teacher 的 KL/一致性约束防止语义回退。
4. **S3 完整部署验证**：预测语义 -> affinity fusion -> reconstruction/watershed -> 类别投票，
   用类别感知实例 mIoU 与铁素体平均面积代理共同选 checkpoint，不用 Oracle 前景指标选模。

最终产物应是一份 phase manifest，记录每阶段输入 checkpoint、数据清单、参数组、随机种子、
阈值与哈希。训练仍是课程式的，但用户只需一个命令启动或从任意 phase 恢复；这才是完整可
复现，而不是只把最后 affinity 命令包装起来。

## 小实例黑边导致语义误判

当前按整实例多数投票会让粗黑边占据小实例的大部分像素，属于训练目标和推理聚合共同造成
的问题。下一轮语义改动应独立于 affinity 阈值实验：

- 训练侧增加按实例等权的 adaptive-core 分类损失、小实例过采样和边缘明暗/厚度扰动；
- 推理侧用实例 distance transform 生成自适应核心权重，以核心概率的 robust mean 投票，
  并在核心过小时回退整实例；
- 固定腐蚀若干像素会让小实例消失，不采用；
- Lab L* 仅在语义概率接近 0.5 时作为每图自适应弱先验，不使用固定全局颜色阈值。

## GPU 利用率诊断与工程优化

本轮 4090 显存稳定约 4.5 GiB、利用率呈短促尖峰，说明不是显存瓶颈，而是小 batch 与
CPU 数据/后处理交替阻塞。当前 `batch_size=2`、DataLoader `num_workers=0`，每个 epoch 还
串行执行 watershed、图匹配、完整部署代理和 monitor I/O。

优先进行不改变算法的吞吐优化：

- 先将 batch size 单变量试到 6，再视显存试 8；为保证实验可比，首轮不线性放大学习率；
- DataLoader 增加 2--4 workers、pin memory、persistent workers 与 prefetch，并监控内存缓存
  是否因 worker 复制而膨胀；
- GPU 批量产出验证概率图后，再在 CPU 侧并行执行逐图 watershed/指标；完整部署评估可每
  2 epoch 做一次，monitor 只在指定 epoch 保存；
- 训练 crop 和光度增强会改变 encoder 输入，不能简单预计算全部冻结 encoder 特征；固定
  验证/测试路径则可以缓存。

该优化预计改善墙钟时间，不与下一轮模型/损失变化混在同一次准确率实验中。
