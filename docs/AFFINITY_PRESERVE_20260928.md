# 最高分 control 的纯分隔恢复消融

## 唯一变量

承接[AFFINITY_TRACE_20260928.md](AFFINITY_TRACE_20260928.md)的细化丢分隔定位，
固定最高分control e20的全部模型和原预测，只开启已有的`restore_marker_partitions`。
本轮不是新的网络结构：复用原保守恢复逻辑，将其与后来添加的面积离群过滤拆开，
观察已有粗边界分隔能否在最终实例中保留，并同时记录新增误切与轮廓重分配。

| 项目 | 控制 | 本轮候选 |
|---|---|---|
| 模型、D5a、输入、融合及阈值 | control e20原链 | 相同 |
| 粗边界分隔恢复 | 关闭 | 开启，原有至少50像素连通核心支持 |
| 附加log-IQR面积离群过滤 | 关闭 | 关闭 |
| 原最小种子／最终实例面积 | 50像素 | 50像素 |
| 实际分水岭障碍图 | 原图 | 逐像素相同 |
| 最终语义 | 原图S-align概率均值复投票 | 相同概率，对新区域复投票 |

新增`inference.marker_partition_restore.area_filter_enabled: false`，
默认仍为true，保证旧恢复＋过滤配置的行为兼容；关闭整个`marker_partition_restore`时保持原部署路径。
本轮不改变图框宽度、不补造内部边界、不按GT或期望实例数／平均面积调整恢复门槛。
恢复逻辑在整图求粗边界反相连通域；不能仅在裁块内判断两侧是否分开。

需要注意：该恢复逻辑会释放一部分旧种子像素，交给分水岭重新生长。
因此即使只增加种子编号，最终也可能出现周围轮廓移动；本次保留并测量这一行为，
没有在同一消融里另加限制生长、图规则或新的过滤规则。

## 检查口径

每个输入只前向产生一组预测，再对这组预测分别执行原解码及候选解码：

1. 截获实际分水岭入口，核对控制种子与独立阶段重建一致。
2. 候选使用完全相同的分水岭图；其种子与独立`restore_marker_partitions`重放逐像素一致。
3. 候选只执行一次分水岭，附加面积阈值为null、过滤数为0；原有50像素最小面积规则仍在。
4. 测试控制实例PNG及类别与原最高分的既有100图输出逐张完全相同。
5. 标注源重现上轮固定代表点关系和实例数；检查结束后比较模型及恢复器的全部状态摘要。

GT只用于事后诊断，恢复算法本身不读取GT。除原先错误点对的修复外，另记录：

- 同一原标可信GT区域内，候选显著碎片之间在旧输出原本同ID的新增误切点对。
- 不同GT可信内部代表点在旧输出已分开、候选中变为同ID的新增粘连。
- 每个GT可信域的显著碎片数增减、已知像素变为背景的数量。

显著碎片仍按至少50像素且至少该GT已知面积10%计算。未标注像素不计入这些诊断。
新增／修复点对不独立，两者采样方式也不同；不能简单相减得到净准确率。
现有GT有遗漏及质量局限，报告采用“按现有GT的诊断”口径，不能将其当测试真实误差。

这些重叠不是296个GT误合并，但说明本次确有轮廓重新分配，而不只是在成品上加一条缝。

小块数下降不能等同于质量提升，实例增多也不等同于正确补分隔。

平均面积下降主要随铁素体实例数增加。这里只描述预测分布，真值方向仍须官方黑盒确认。

## 判断边界

用户随后回报本包官方成绩为 **0.8499／0.8559（85.290）**，当前官方最佳仍为control e20的
**0.8486／0.8761（86.235）**。同权重单变量比较：mIoU＋0.0013，面积项−0.0202，综合−0.945分，不晋级。
新回分单独记录于私有`output/affinity_review/official_score.json`；保留生成时`report.json`无成绩的历史快照。
包SHA256已重新核对，与上节一致。新的面积分层和下一步详见[AFFINITY_REVIEW_20260928.md](AFFINITY_REVIEW_20260928.md)。
历史旧语义LoRA链上的“恢复＋过滤”回退0.870分不能拆给某一个子步骤，
也不能与本次不同权重的结果直接构成严格消融。
本轮能检验的是：在当前最高分模型上，单独恢复已有分隔的具体收益与副作用。
已获得这次固定方案的官方对照；未与阈值、过滤或新训练叠加。
既然回退，应优先利用已记录的新误切与重生长副作用定位，而不是继续增加恢复强度或强行回调平均面积。
